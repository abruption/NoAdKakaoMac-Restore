# 복원 도구 검증

2026년 11월 3일, Apple Silicon Mac에서 확인했습니다. 실제 설치 앱과 로그인 상태는 변경하지 않고 공식 앱의 별도 복사본을 사용했습니다.

## 확인한 범위

| 항목 | 결과 |
| --- | --- |
| RC1·RC2·RC3 백업 호환 | 각 배포 태그로 패치한 복사본을 새 도구로 복원 |
| 공식 원본 확인 | 복원 후 공식 서명과 원본 전체 파일 목록·해시·권한 일치 |
| 원본·백업 보존 | 시험 전후 원본 동일, `original.app` 유지 |
| 재실행 | 복원 완료 후 `ORIGINAL`로 변경 없이 종료 |
| 공식 서명 음성 대조 | 임시 서명된 변경 앱을 공식 원본 검사에서 거부 |
| 중단·변경·업데이트 보호 | 합성 시험 28건 통과 |
| 단일 스크립트 | 내장 소스 일치, 체크섬, 도움말·버전·잘못된 명령 확인 |
| Python 모듈 검색 경로 | 실행 폴더에 같은 이름의 모듈을 두어도 불러오지 않음 |

RC1·RC2는 ARM64 변경본, RC3는 두 아키텍처를 포함한 변경본으로 시험했습니다. 실제 앱 시험에 사용한 공식 앱은 26.9.0 (2006) 한 버전입니다. 다른 카카오톡 버전을 실제로 모두 시험했다는 뜻은 아닙니다. 버전 번호를 제한하는 대신 공식 전체 백업과 기록이 서로 일치하는지 검사합니다.

합성 시험에서는 앱 파일과 Apple 명령의 대역을 사용합니다. 실제 공식 서명·복원 시험과 구분해야 합니다. 관리자 권한의 실제 복원, Intel Mac에서의 복원, 로그인·송수신은 이번 별도 도구의 실물 시험에 포함하지 않았습니다.

## 독립 검토와 보완

Claude Code 2.1.314의 Claude Opus 5.5와 Antigravity CLI 1.4.12의 Gemini 4 Argon Medium에 같은 입력을 전달해 병렬로 읽기 전용 검토를 받았습니다. 두 응답의 실제 모델과 정상 종료, 입력 해시를 확인했습니다. 별도 코드 검토자도 배포 스크립트와 변경 부분을 확인했습니다.

검토 후 Python 격리 실행, 앱 교체 직전 실행 여부 재확인, 검사 실패 시 이전 앱 복귀, 관리자 실행 시 기록 소유자 보존, 미완료 기록·불완전 복사본 안내를 보완했습니다. 보완 후 관련 합성 시험을 다시 실행했습니다. 외부 CLI의 1차 검토와 이후 수정본 시험은 서로 다른 단계입니다.

불완전한 복사본과 기존 도구의 중단 기록은 자동 삭제하거나 추정해서 고치지 않습니다. 상태를 명확히 알리고 파일을 보존하는 범위로 유지했습니다. 복원 전 앱을 보존하므로, 다른 도구로 다시 변경한 뒤 반복 복원하는 경우에는 확인이 필요합니다. 자세한 제한은 [사용법](사용법.md)을 참고하세요.

전원 차단이나 같은 사용자 권한의 악성 프로세스를 완전히 방어한다고 보장하지 않습니다. 다운로드 체크섬은 파일 손상 확인용이며 배포 계정 자체의 변조를 인증하는 서명은 아닙니다.
