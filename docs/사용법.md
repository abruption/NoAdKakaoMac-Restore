# 사용법

## 준비

- macOS와 Python 3.9 이상이 필요합니다. `python3 --version`으로 확인합니다.
- NoAdKakaoMac RC1~RC3가 만든 정상적인 전체 백업이 필요합니다. 같은 백업 폴더 안에 `manifest.json`과 `original.app`이 있어야 합니다.
- 카카오톡을 완전히 종료하고 복원이 끝날 때까지 다시 실행하지 않습니다. 창만 닫으면 앱이 계속 실행 중일 수 있습니다. App Store에서 업데이트 중일 때도 실행하지 않습니다.
- 원본 앱을 복사할 수 있는 여유 공간을 확보합니다. 복원 전 앱도 보존하므로 복원 직후 공간이 자동으로 줄어들지는 않습니다.

이 도구는 카카오톡 버전별 패치 목록을 사용하지 않습니다. 대신 백업의 공식 서명과 전체 파일을 확인하고, 현재 앱이 그 백업에 기록된 변경 앱과 같은지 확인합니다. 따라서 버전 제한이 없다는 말은 모든 앱을 백업 없이 고칠 수 있다는 뜻이 아닙니다. 손상되거나 알 수 없는 형식의 백업은 사용할 수 없습니다.

## 1. 배포 파일 받기

[v0.1.0-rc.1 릴리즈](https://github.com/abruption/NoAdKakaoMac-Restore/releases/tag/v0.1.0-rc.1)에서 제공하는 `restore.sh` 하나로 실행합니다. 터미널에서 다음 명령으로 스크립트와 확인용 파일을 내려받습니다.

```sh
curl -fLO https://github.com/abruption/NoAdKakaoMac-Restore/releases/download/v0.1.0-rc.1/restore.sh
curl -fLO https://github.com/abruption/NoAdKakaoMac-Restore/releases/download/v0.1.0-rc.1/SHA256SUMS
shasum -a 256 -c SHA256SUMS
```

`restore.sh: OK`가 표시되어야 합니다. 다운로드나 확인에 실패하면 스크립트를 실행하지 말고 다시 내려받습니다. 이후 명령도 다운로드한 폴더에서 실행합니다. Python 코드는 스크립트에 포함되어 있지만, 실행할 Python 3.9 이상은 Mac에 설치되어 있어야 합니다.

## 2. 상태 확인

```sh
sh restore.sh status
```

기본 앱 경로는 `/Applications/KakaoTalk.app`입니다. 백업은 현재 사용자의 `~/Library/Application Support/NoAdKakaoMac/backups`에서 찾습니다. 관리자 권한으로 실행할 때도 `sudo`를 실행한 사용자의 백업을 찾습니다.

상태와 복원 결과는 JSON으로 표시됩니다. Python 미설치 등 실행 전 오류와 명령 구문 오류는 일반 문장으로 표시됩니다.

| `state` | 의미와 다음 단계 |
| --- | --- |
| `ORIGINAL` | 공식 서명이 유효한 앱입니다. 복원할 필요가 없습니다. |
| `RESTORABLE` | 기록과 전체 원본 백업을 확인했습니다. 다음 단계로 진행합니다. |
| `RECOVERY_REQUIRED` | 이 복원 도구의 작업이 중단되었습니다. 파일을 옮기거나 지우지 말고 `restore`를 다시 실행합니다. |
| `ERROR` | 확인 또는 복원을 중단했습니다. 함께 표시된 `code`와 `message`를 확인합니다. |

이전 도구가 관리자 권한으로 남긴 파일 때문에 상태 조회에서 권한 오류가 나면 `sudo sh restore.sh status`로 확인합니다.

## 3. 복원

```sh
sh restore.sh restore
```

권한 부족 오류가 발생한 경우에만 다음과 같이 실행합니다.

```sh
sudo sh restore.sh restore
```

복원이 끝나면 `RESTORED`와 함께 복원 전 앱을 보존한 `previous_app` 경로가 표시됩니다. 기존 카카오톡 아이콘으로 실행할 수 있습니다. 이 도구는 로그인이나 메시지 송수신을 시험하지 않습니다. 필요한 확인은 사용자가 직접 진행하세요.

## 앱 또는 백업 폴더 지정

앱이 다른 경로에 있으면 `--app`을 지정합니다. 백업을 다른 곳에 보관했거나 같은 앱의 백업이 여러 개면 `--backup-dir`을 지정합니다. 경로에 공백이 있으면 따옴표로 감쌉니다.

```sh
sh restore.sh status \
  --app "/Applications/KakaoTalk.app" \
  --backup-dir "$HOME/Library/Application Support/NoAdKakaoMac/backups/백업폴더명"
```

확인이 끝나면 같은 경로로 복원합니다.

```sh
sh restore.sh restore \
  --app "/Applications/KakaoTalk.app" \
  --backup-dir "$HOME/Library/Application Support/NoAdKakaoMac/backups/백업폴더명"
```

`백업폴더명`은 실제 폴더 이름으로 바꿉니다. `--backup-dir`에는 `original.app` 자체가 아니라 `manifest.json`과 `original.app`이 들어 있는 상위 폴더를 지정합니다. 원래 기록된 앱 경로가 다르면 복원하지 않습니다. 기록 파일을 직접 수정하지 마세요.

## 보존되는 파일과 중단 조건

복원은 전체 원본을 별도로 복사해 확인한 뒤 설치합니다. 원본 백업은 그대로 남기고, 복원 전 앱은 앱 폴더 옆의 숨김 경로에 보존합니다. 이 도구는 이 파일들을 자동으로 삭제하지 않습니다.

공식 서명이 유효한 앱은 업데이트 여부와 관계없이 그대로 둡니다. 구버전 백업을 업데이트된 공식 앱 위에 설치하지 않습니다. 현재 앱의 파일이 기록과 다르거나 서명을 확인할 수 없으면 임의로 고치지 않고 중단합니다.

NoAdKakaoMac에서 남긴 `transaction.json`, `preparation.json`, 준비 중인 앱 등의 기존 중단 파일은 자동 처리하지 않습니다. 오류에 표시된 경로를 보존하고 원인을 확인하세요. 파일을 지워 검사를 통과시키려고 하지 마세요.

이 복원 도구 자체의 작업이 중단된 경우에는 같은 앱·백업 경로로 `restore`를 다시 실행합니다. 준비 파일과 기록이 서로 일치하는 경우에만 이어서 진행합니다. 불완전한 복사나 파일 변경이 발견되면 다시 중단하므로, 재실행이 모든 중단 상태를 해결하지는 않습니다.

## 원본 백업이 없는 경우

이 도구는 공식 앱을 내려받거나 변경된 실행 파일에서 원본을 추정하지 않습니다. 사용할 수 있는 전체 원본 백업이 없다면 카카오톡을 공식 배포처에서 다시 설치하세요. 대화 자료·첨부파일·사용자 데이터 폴더를 삭제하지 마세요.

문제가 계속되면 [GitHub Issues](https://github.com/abruption/NoAdKakaoMac-Restore/issues)에 오류 코드와 설명을 남겨 주세요. 사용자 이름이 포함된 경로는 가리고, 백업·앱 파일·대화 내용·로그인 정보는 올리지 마세요.

복원할 때마다 고유한 경로에 복원 전 앱을 보존합니다. 이전 복원에서 남긴 앱이 있어도 그 파일을 옮기거나 삭제하지 않고 새 경로를 사용합니다. 기록 없는 준비 파일이 남아 있거나 현재 앱·백업 검증에 실패하면 계속 중단합니다.

## 복구 실패 진단

앱과 백업, 중단 기록은 그대로 두고 다음 명령으로 진단 스크립트를 내려받습니다. 진단 스크립트는 단독으로 실행할 수 있으며, `restore.sh`와 같은 폴더에 둘 필요가 없습니다. macOS와 Python 3.9 이상이 필요합니다.

```sh
curl -fLO https://github.com/abruption/NoAdKakaoMac-Restore/releases/download/v0.1.0-rc.1/diagnose.sh
curl -fLO https://github.com/abruption/NoAdKakaoMac-Restore/releases/download/v0.1.0-rc.1/diagnose.sh.sha256
shasum -a 256 -c diagnose.sh.sha256
sh diagnose.sh
```

다른 앱이나 백업 폴더를 사용했다면 복원할 때와 같은 경로를 지정합니다.

```sh
sh diagnose.sh \
  --app "/Applications/KakaoTalk.app" \
  --backup-dir "$HOME/Library/Application Support/NoAdKakaoMac/backups/백업폴더명"
```

관리자 권한으로 복원하다 실패했다면 우선 일반 권한으로 진단합니다. 결과가 권한 오류(`IO_ERROR`, `errno: 13`)라면 같은 경로로 `sudo sh diagnose.sh`를 실행한 결과도 함께 알려 주세요.

진단은 앱·백업·중단 기록을 변경하거나 삭제하지 않으며 네트워크 전송도 하지 않습니다. 결과는 화면에만 표시됩니다. 다음 정보만 요약합니다.

- 도구·macOS·Python 버전, 실행 아키텍처, 관리자 권한 여부
- 현재 앱 상태와 버전, 기록의 형식·상태
- 백업·잠금·중단 파일의 유무와 접근 가능 여부·권한
- 상태 확인 오류 코드와 파일 접근 오류 번호

사용자 이름이 담긴 경로, 컴퓨터 이름, 기기 일련번호, 대화·첨부파일, Keychain·로그인 정보는 수집하지 않습니다. 외부 명령이 출력한 원문 오류도 제보 결과에 포함하지 않습니다. 아키텍처 값은 현재 실행 환경이며 실제 Mac 칩 종류를 확정하는 값은 아닙니다.

[오류 제보 양식](https://github.com/abruption/NoAdKakaoMac-Restore/issues/new/choose)에 상황과 재현 순서, 오류 코드, JSON 진단 결과를 붙여 넣으세요. 진단 결과를 만들었다는 뜻의 종료 코드 `0`은 복원이 가능하다는 뜻이 아닙니다. JSON의 `status.state`와 `status.code`를 확인합니다. 진단 스크립트를 실행할 수 없다면 기존 오류 코드만으로 제보해도 됩니다. 앱·백업과 원시 로그는 첨부하지 마세요.

2026년 11월 3일 RC1 첨부 파일을 수정본으로 교체하고 `diagnose.sh`를 추가했습니다. 기존 복원 파일을 받았다면 다시 내려받으세요. `SHA256SUMS`는 복원 파일을, `diagnose.sh.sha256`은 진단 파일을 확인합니다. 수정된 소스 기준은 릴리즈 설명의 커밋 링크를 참고하세요.
